# Phase 0 · 技术验证方案（预研）

> [!important] 只预研，不编码。所有选型完成并在 [[04-开发前准备工作清单]] 打勾后才开工。

## 1. 验证目标

**唯一赌注**：一句话需求 → "行家看了说没毛病"的型材结构方案。
**验收**：10条真实需求描述，≥8条生成合格方案（合格=选型正确、连接方式合理、孔位加工参数正确、清单可直接采购）。

## 2. 技术链路

```
自然语言需求
  → ① LLM 参数抽取（结构化 JSON）
  → ② 参数化框架生成（确定性代码）
  → ③ 规则引擎：选型/连接决策/加工参数/校验
  → ④ 输出：Three.js 3D + 切割清单 + BOM + 参考价
```

## 3. 各层选型（待定项用 ❓ 标注）

### ① 意图层
- LLM 结构化输出（JSON Schema 约束）
- 抽取字段：外形尺寸(W/D/H)、用途、承重、层数/隔板、脚轮/脚杯、颜色、预算敏感度
- 缺失信息策略：追问 vs 默认值 ❓（Demo阶段建议默认值+标注假设）
- 模型选择 ❓：国内API（成本/合规） vs OpenAI/Anthropic

### ② 生成层
- 输入：结构参数 JSON；输出：构件图（型材段列表 + 节点连接关系）
- 正交框架生成算法：立柱/横梁/纵梁布局，隔板层逻辑
- 语言选型 ❓：TypeScript（与前端同栈，Three.js无缝） vs Python（build123d/CAD生态）
- Demo建议：TypeScript 全栈（Next.js + Three.js），几何简单用不到CAD内核

### ③ 规则层（知识库，核心资产）
格式：YAML/JSON 配置，禁止硬编码。需要整理的规则包：

1. **型材选型表**：跨度/承重 → 系列（20/30/40）与截面（2020/2040/3030/4040...）
2. **连接方式决策树**：受力方向 + 可拆卸性 + 外观 → 角码/内置/锚式/口哨连接件
3. **加工参数表**（源：嘉立创工艺页，见 [[01-竞品分析-嘉立创FA]]）：
   - 端面攻牙：系列 → 中心孔径/螺纹/深度
   - 沉头孔/扳手孔/锚式通孔/口哨盲孔：系列 → 孔径/孔位公式（如 G=19-T+2）
4. **配件映射表**：连接方式+系列 → 螺栓/螺母/连接件具体型号
5. **价格表**：型材单价/米 + 配件单价 + 加工单价（Demo用嘉立创公开价）
6. **校验规则**：最大跨度限制、承重粗算（悬臂/简支梁公式）、槽口朝向冲突

### ④ 输出层
- Three.js：型材用挤出截面或简化长方体+槽口贴图 ❓
- 清单：切割清单（型号/长度/数量/加工项）、连接件BOM、总价估算

## 4. 关键技术风险预研题

- [ ] LLM 参数抽取的稳定性：同一需求多次提问，参数是否一致？
- [ ] 连接方式决策树能否覆盖工作台/置物架的90%场景？
- [ ] 承重粗算公式的可信度（找机械专业朋友评审）
- [x] 型材3D截面数据从哪来：**已解决（2026-08-04）**——截面即2D数据、运行时挤出（嘉立创同架构，加载日志证实；Three.js ExtrudeGeometry），截面轮廓自建或从公开DXF描摹
- [ ] 嘉立创价格数据获取方式与合规性 ❓
- [ ] 实测嘉立创"整体尺寸"工具：改整体尺寸后构件长度/连接件是否全联动（其约束传播能力=我方引擎对标基线）

## 5. Demo 范围红线（防止膨胀）

- 只支持：矩形正交框架 + 隔板 + 脚轮/脚杯
- 不支持：斜撑、异形、门板铰链、抽屉
- 不做：登录、支付、手机端、自由拖拽设计器
- UI 一页即可：输入框 + 3D窗口 + 清单表格
