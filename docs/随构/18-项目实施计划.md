# 随构 · 项目实施计划

> [!info] 计划定位

- 精确 STEP/DXF 和梁框架分析尚未验证。

## 二、项目目标与成功标准

### 2.1 Phase 0 完成目标

> 用 10 条真实需求证明：随构能稳定生成正交铝型材框架，并输出行家认可、装配完整、风险可解释的方案。

必须同时满足：

- 10 条真实需求中至少 8 条达到“行家看了没明显问题”。
- 0 个已知不兼容方案可导出。
- 0 个可见采购零件缺失于 BOM。
- 0 个板材/附件没有 Mount。
- 所有高风险方案明确显示未验证项。
- 从生成到导出无白屏和未捕获异常。
- 测试可由命令一次执行，不依赖手工查看 Golden UI。

### 2.2 Phase 1 进入条件

- M5 通过。
- 至少 5 名目标用户完成任务测试。
- 至少 2 个真实方案完成线下装配验证。
- BOM、加工与实际装配差异形成记录并修正。
- 明确首个付费交付物：方案费、制造包或代购服务。

## 三、执行原则

1. **先修错误输出，再扩能力**。
2. **先做真实装配闭环，再做 CAD 精细外观**。
3. **每个里程碑只解决一个主要风险**。
4. **所有新能力必须同时进入模型、校验、BOM、Viewer 和测试**。
5. **不因引入开源引擎重写现有主链**。
6. **评测结论必须转成可执行验收，不只写建议**。
7. **每个里程碑独立提交、独立回归、独立记录到 [[14-Phase0-开发日志]]**。

## 六、M5：真实需求回归验收

### 目标

验证产品是否解决真实问题，而不是只证明内部规则自洽。

### 输入

使用 [[13-需求测试集]] 中与 Phase 0 范围匹配的需求，选出 10 条原生组用例，至少覆盖：

- 工作台、置物架、设备架、水族高风险。
- 固定脚与脚轮。
- 木板、玻璃、亚克力。
- 集中载荷和均布载荷。
- 缺尺寸、缺载荷、含超纲需求。

### 每条用例记录

```text
原始需求
→ 抽取结果
→ 追问与回答
→ 最终 FrameSpec
→ 结构/装配/BOM
→ 校验与未验证项
→ 行家结论
→ 缺陷归因
```

### 评分维度

| 维度 | 权重 | 判断 |
|---|---:|---|
| 意图正确 | 20% | 没有编造关键参数，追问命中 |
| 几何正确 | 20% | 尺寸、层数、位置正确 |
| 装配完整 | 20% | Joint/Mount/Fastener/Accessory 完整 |
| 制造一致 | 20% | 切割、加工、BOM 与模型一致 |
| 风险表达 | 20% | 错误阻断、假设与未验证项清楚 |

### 验收

- [ ] 至少 8/10 达到 80 分。
- [ ] 所有失败按“意图/知识/生成/装配/校验/界面”归因。
- [ ] 不允许通过修改期望值掩盖真实问题。
- [ ] 形成 M5 评测报告和下一轮缺陷排序。

## 八、M6：工作台体验重构

## 十、M8：RepliCAD / STEP PoC

### 目标

验证浏览器 CAD 内核是否值得进入主线，不以“成功安装”作为完成。

### 范围

单独建立 Adapter/实验分支，验证：

- 2020/3030/4040 截面拉伸。
- 局部孔位、攻丝/沉头的几何表达边界。
- 板材和连接件简单实体。
- 多零件 STEP 导出与名称映射。
- Web Worker 加载与取消。

### 决策门

- [ ] STEP 在 FreeCAD 打开，数量、名称、坐标与 BOM 一致。
- [ ] 连续重建 100 次无明显内存增长。
- [ ] 首次加载和方案更新在可接受时间内。
- [ ] CAD 失败不会阻塞 Three.js 和 BOM。
- [ ] 许可证通知与源码获取方式准备完成。

不通过则停止浏览器 CAD 主线，转 Phase 1 后端 build123d/CadQuery。

## 十四、风险登记

| 风险 | 概率 | 影响 | 应对 |
|---|---|---|---|
| 领域知识错误 | 中 | 极高 | 来源分级、行家审核、真实装配 |
| 扩 SKU 后组合爆炸 | 高 | 高 | 能力矩阵、契约测试、兼容集合选择 |
| FEA 结果被过度信任 | 中 | 极高 | 明示假设、预校核措辞、人工复核 |
| LLM 多轮误解 | 中 | 高 | 显式字段、结构化 history、确认步骤 |
| CAD 内核过重 | 中 | 中 | Adapter PoC、Worker、后端备选 |
| 单人范围失控 | 高 | 高 | 里程碑门禁、不做清单、每轮一个风险 |
| 供应商数据变化 | 高 | 中 | 版本、来源、更新时间、替代关系 |
| 许可证遗漏 | 低中 | 高 | SBOM、NOTICE、法务复核 |

## 十五、需求变更规则

新需求进入计划前必须回答：

1. 是否服务当前目标用户？
2. 是否影响制造正确性或安全？
3. 是否在当前范围内？
4. 需要修改哪些领域实体？
5. 是否能同时完成 Viewer、BOM、校验和测试？
6. 会推迟哪个当前里程碑？

若无法回答，不进入开发，只进入评测/候选池。

## 十六、完成定义（Definition of Done）

任何结构能力只有同时满足以下条件才算完成：

- [ ] 输入 Schema 可表达。
- [ ] 领域模型有对应实体和关系。
- [ ] 确定性生成器可生成。
- [ ] 兼容与安全规则覆盖。
- [ ] Viewer 可见且可检查。
- [ ] BOM、加工和价格完整。
- [ ] 错误状态能阻断导出。
- [ ] 自动测试与 Golden 覆盖。
- [ ] 用户文案说明假设和边界。
- [ ] 开发日志记录提交与验收证据。

只完成 3D 显示不算完成；只增加下拉选项不算完成；只写规则但不进入质量闸门也不算完成。
