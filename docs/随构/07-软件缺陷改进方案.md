# 随构 · 软件缺陷改进方案

> 针对 [[06-项目全面审视与增长策略]] 中可用工程手段解决的缺点（1/3/4/5）与高风险项（结构安全措辞）的细化设计。
> 总原则：**宁可不答，不可错答。**

## 一、缺点1：无机械行家 → 知识库质量保障体系

行家时间稀缺，用工程手段放大其价值：

- **规则元数据**：每条规则带 来源（嘉立创工艺页/国标/推断）、置信度（已验证/公开资料/推断 三级）、评审状态、适用范围
- **置信度驱动生成**：仅"已验证/公开资料"级可直接生成；"推断"级参与时方案强制标注"基于推断，建议核实"
- **规则即代码 + Golden 单测**：每条规则配测试用例（输入→期望输出），CI 自动跑；行家评审"规则+用例"，一次评审永久锁定
- **知识库 git 版本化**：修订可追溯可回滚，坏规则可定位影响面

## 二、缺点3：LLM成本 → 成本控制架构

核心：LLM 只在意图层一个点，且可大量绕过。

- **调用最小化**：微调方案（改尺寸/颜色/材料）走参数化引擎零LLM；一个会话理论1-2次调用
- **模型分层路由**：参数抽取用小模型；多轮澄清对话才用大模型
- **语义缓存**：需求归一化+embedding相似度，"1米2工作台"="120cm工作桌"
- **限额熔断**：匿名N次/天、登录更高；日成本看板+超阈值熔断降级
- **成本埋点**：每次调用记录，第一天就知道单方案成本

## 三、缺点4：生成质量长尾 → 质量保障管道

- **LLM 零几何权**：只输出参数JSON；Schema校验+数值范围校验（异常值拒绝并要求确认）；幻觉字段丢弃
- **四层校验管道**（任一层不过→不出方案，转为追问）：
  1. Schema/范围校验（参数合法性）
  2. 物理合理性（跨度/承重/比例）
  3. 几何校验（构件碰撞、连接点可行性）
  4. BOM完整性（每个连接有配件、每个孔有工艺）
- **Golden回归集**：30条真实需求（准备清单A区）即回归集；规则/提示词/模型任何改动全量跑，输出diff人工过目
- **方案自动评分器**：规则覆盖率/公差合规/成本合理性打分，低分不展示
- **影子运行**：新规则包先只记录不生效，对比稳定后启用

## 四、缺点5：超纲需求 → 优雅降级设计

"这个我不会"说得好比硬答更圈粉：

- **能力边界显式建模**：capability manifest（结构×材料×工艺覆盖清单）；意图分类前置：完全支持/部分支持/不支持
- **部分支持（精髓）**：生成能做的部分+明确标注超纲部分+**预留安装接口**（"弯管滑梯超纲，此处已留接口可外购加装"）——超纲变开放接口
- **不支持**：诚实回复+一键"催更"
- **超纲需求日志**：品类扩展的真实投票，每周看top未覆盖需求决定下个规则包——张力变进化导航仪

## 五、高风险项：结构安全措辞 → 软件层强制

- **措辞库统一管理**：输出模板禁用"保证/承诺/安全"断言词，统一"估算参考/理论值"
- **输出强制三要素**（模板层硬编码不可绕过）：估算依据+假设条件+免责提示
- **高风险场景标签**（水族/儿童/悬挂/超高）：触发显性警示+自动加大安全系数
